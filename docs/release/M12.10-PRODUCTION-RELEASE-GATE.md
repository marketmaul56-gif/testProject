## Accepted environment/engineering debt

### TD-01 — Provider-specific production binding

Risk: a provider-neutral release candidate is not itself a live production environment.

Why acceptable for MVP baseline: M3 deliberately deferred vendor selection; application contracts are provider-neutral and executable.

Required before live traffic: select provider/account/region; bind OpenTofu; record immutable registry digests; configure external secrets; run production smoke.

### TD-02 — Observability backend and alert channels

Risk: OTLP instrumentation exists but alert routing has not been proven against a selected backend.

Mitigation: `DEPLOYMENT-TARGET.md` defines mandatory alerts. Test alerts before live traffic.

### TD-03 — Managed PostgreSQL PITR/RPO evidence

Risk: CI proves logical restore integrity, not provider backup scheduling.

Mitigation: configure RPO <= 15 minutes and rehearse provider restore against the selected environment before launch.

### TD-04 — Main branch protection

Risk: current repository `main` is not protected by enforced required checks/review.

Why accepted at M12 lock: it does not alter runtime/product authority semantics and cannot be configured through the current connector administration scope.

Trigger to close: before using `main` as the routine production promotion branch, enable protected-main required checks + PR review according to M4.
