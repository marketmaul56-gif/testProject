## Critical runtime-flow finding

The repository currently exposes learner/instructor read APIs, instructor formative guidance, authentication, readiness, and AI coaching. The canonical practice/project verification journey is proven at service/database test level, but the production API/runtime tree does not currently expose a complete learner submission → verification-dispatch → trusted authority-processing path, and there is no executable trusted worker runtime under `apps/worker`.

This is **not a deployment-only gap**. Shipping an RC while the authoritative flow can only be driven by test/service harnesses would violate the M12 release blocker rule “critical flow unusable”.

A formal bounded Change Review is recorded in `docs/release/CHANGE-REVIEW-M12.9-RUNTIME-WIRING.md`. It remains **PENDING EXPLICIT APPROVAL**. No locked implementation milestone will be changed until that approval exists.
